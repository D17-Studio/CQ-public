# 谱面新结构适配计划

> 依据：`_Project/Design/谱面重构/新结构.md`
> 状态：执行中（Phase 1 数据层与序列化适配器完成；Phase 2 判定/输入/视觉主要接线完成，真实谱面已接入、实机验收待做，Length 未接）。进度见「执行进度」。

## Context

新结构定义了单 LaneIndex、ChannelCurve、六类 LaneEvent（Transform/Opacity/Length/Speed/Zone/Parent）与 Fake 模式。当前代码仍使用自定义 DSL + `LaneMotionData`/`LaneKeyframe`/`LaneState`/`JudgeLaneIndex[]`/`ViewLaneIndex`/Note 级流速，与新结构全面冲突。

本计划目标：把共享层与 Unity 运行时分阶段迁移到新结构；制谱器不在本次实施范围，另行交接。**Lane 今后只表示视觉轨道，判定按键统一由 Zone 表达。**

### 序列化格式（已定稿）

> JSON + Newtonsoft.Json。Unity 通过 `com.unity.nuget.newtonsoft-json`（3.2.1）引用；制谱器与临时验证工程使用 NuGet `Newtonsoft.Json 13.0.3`。

```json
{
  "Version": 1,
  "Bpm": [ { "StartTime": 0, "Bpm": 170 } ],
  "Notes": [
    { "Type": "Dot", "LaneIndex": 0, "TargetTime": 4236, "SustainDuration": 0,
      "AppearOffset": -3000, "Fake": null, "LinkedTunes": null }
  ],
  "LaneEvents": {
    "Transform": [],
    "Opacity":   [ { "LaneIndex": 0, "StartTime": 0, "Duration": 200, "Layer": 0,
                     "Targets": "Head, Line, Label, Note",
                     "ValueCurve": { "From": 0, "FromMode": "Absolute", "To": 1, "ToMode": "Absolute", "Ease": "Linear" } } ],
    "Length": [],
    "Speed": [],
    "Zone":   [ { "LaneIndex": 0, "StartTime": 0, "TargetZone": "L1" } ],
    "Parent": []
  }
}
```

- **格式规则**：字段 PascalCase；枚举写字符串且拒绝数字；flags 逗号分隔；null 字段写档时省略；未知字段读取时忽略。
- **序列化边界**：`ChartSheet` 只持有模型；读写由 `ChartSerializer.Deserialize(string)` / `Serialize(ChartSheet)` 负责；`ChartSheet.Parse(string)` 仅为薄转发。模型本身不出现 Newtonsoft 特性或 `using`。
- **构造方式**：构造函数接收模型集合（Note、六类事件、BPM），统计与 `LaneIndexList` 在构造时计算；单 string 入口为 `ChartSheet.Parse`。
- **校验与失败语义**：必填字段（Note 的 Type/LaneIndex/TargetTime、事件核心字段、ChannelCurve 五字段）用 `[JsonRequired]`；解析失败抛 `ChartException` 并保留字段路径与行列号；缺 `Version` 按 1 处理并告警；空文本为坏档，空 Notes 仅告警；运行时 `LogError` 并中止安装。
- **往返验证**：临时工程已通过全类型往返、同刻顺序、`Serialize→Deserialize→Serialize` 稳定性与 11 类坏档测试。
- **文件载体**：谱面继续由 `ChartInfo.ChartText`（Unity TextAsset）读取，扩展名保持 `.txt`；内容格式与扩展名无关，避免改扩展名带来的资产/meta 改动。
- **排序与同刻语义**：`Sort()` 使用稳定排序（按时间；LaneEvent 同 `StartTime` 时按 `Duration` 降序，长者在前；其余同时间保持写入顺序）。Zone/Parent 等瞬时事件在求值时取最后一条 `StartTime <= time`，同刻后写覆盖；序列化往返必须保持该顺序。

## 二、运行时采样架构（`LaneState` 重写）

### 数据组织与求值（不使用 LaneKeyframe）

每条 Lane 持有独立通道列表：X、Y、Rotation、Head/Line/Label/Note Opacity、Length、Speed；Zone、Parent 为瞬时列表。不生成 `LaneKeyframe`，也不使用 `PreCurve` 对象链；回退语义保留，由 `LaneState` 扫描通道列表实现。

条目结构：

```csharp
struct LaneChannelEntry
{
    public int StartTime;
    public int Duration;
    public float StartValue;
    public float EndValue;
    public EaseCurve Ease;
    public bool DoPersistEnd;

    // 仅 X / Y 条目使用
    public Vec2 Anchor;
    public int RotationEntry;   // 同 Lane 的 Rotation 通道条目索引，-1 = 无
}

struct LaneSpeedEntry { public LaneChannelEntry Curve; public LaneSpeedMode Mode; }
```

构建规则：

1. 六类事件按 `StartTime` 排序（`ChartSheet.Sort()` 保证）。
2. 事件按子通道展开：Transform → X/Y/Rotation；Opacity → 命中的 Head/Line/Label/Note；Length/Speed → 各一条。
3. 每个子通道的 `ChannelCurve` 解析为绝对 `StartValue/EndValue`：
   - `FromMode=Absolute` → `StartValue = From`
   - `FromMode=Relative` → `StartValue = 当前该通道输出(事件开始时刻) + 本条目补偿(事件开始时刻) + From`
   - `ToMode=Absolute` → `EndValue = To`
   - `ToMode=Relative` → `EndValue = StartValue + To`
   - X/Y 的「本条目补偿」用同 Transform 的 `Anchor` 与该事件的 Rotation 曲线在事件开始时刻的值；无 Rotation 曲线则为 0。
4. `DoPersistEnd`：若同通道更早的条目窗口仍覆盖本条目结束时刻（`StartTime <= end && StartTime + Duration > end`），则为 false；否则为 true。
5. X/Y 条目记录同 Transform 的 `Anchor` 与 Rotation 条目索引；Rotation 条目正常加入 Rotation 通道。

求值规则：

1. 通用通道：从后向前找最后一个 `StartTime <= time` 的条目；条目在窗口内或 `DoPersistEnd == true` → 按 `Duration/Ease` 求值返回；否则继续向前回退；全部无效 → 通道默认值。
2. X/Y：按通用通道规则求值后，用条目自己的 `Anchor` 和引用 Rotation 条目的曲线值做补偿（`dx = ax·cosθ - ay·sinθ`，`dy = ax·sinθ + ay·cosθ`）；引用条目只做曲线求值，不检查其是否生效；无 Rotation 引用则不补偿。
3. X 与 Y 独立回退，允许来自不同 Transform 条目；各自用自己条目的 Anchor/Rotation 补偿。
4. Rotation、四种 Opacity、Length 直接使用通用通道求值；Speed 额外返回 `Mode`；Zone/Parent 取最后一条 `StartTime <= time` 的事件，无则默认值；同 `StartTime` 时取列表顺序最后一条（稳定排序保证编辑顺序）。

**Zone 的运行时归属**：谱面文件中 Zone 存于 `LaneEvent.Zone`（便于按 Lane 时间轴编辑）；运行时在创建 `Note` 时按 `TargetTime` 采样一次，固化为 Note 属性。判定窗口、长条持续、Mute 自动判定全程使用该固化值。

**Speed 求值**：

- 有效速度：`Multiplier` → 玩家全局流速 × 曲线值；`Fixed` → 曲线值；无事件 → 玩家全局流速。
- 允许 0 与负值，不钳制。
- 距离 = `∫[now → 点的正解时间] 速度曲线 dt`；曲线按 Ease 做解析积分（`Easing.Integral`），Multiplier/Fixed 按区间各自生效。
- 所有节点共用 Note 头部 Lane 的曲线；单节点与多节点（Mute 头/尾、Dash 头/Tune 点/尾点）只差积分上限（各自目标时间）。
- Mute 最小视觉长度不在 shared 计算层处理；如需要由游戏侧视觉层实现（当前未实现）。

**Tune 运行时**：

- `Tune.TargetLane` 是绝对视觉轨道号；Dash 头与 Tune 前过渡点用当前 Lane，Tune 目标点用 `TargetLane`。
- 每个点用自身 Lane 的 `GetFrame(lane, 当前时间)`（含 Parent 合成）取位置/旋转。
- `UseRelative=true`：偏移按目标 Lane 的旋转换算；`UseRelative=false`：`PosValue` 为世界坐标。
- `Duration` 是到达目标点后的过渡时长，保持旧插值行为。
- 速度统一取 Note 头部 `LaneIndex` 的流速曲线，按各点自身目标时间积分。

**Length 求值**：

- 值 = 轨道线视觉长度倍率，1 = prefab 原始长度。
- 缩放基准在轨道头/判定线（Sprite 轴心底部），向上延伸；Head/Label 位置与 Note 下落距离不受影响。
- 允许 0 与负值，不钳制；负值翻转轨道线。
- Parent 只合成 Transform，不继承 Length。

**NoteOpacity 求值**：

- 每帧对 NoteView 的所有 submesh（描边 + 填充）乘入 `LaneState.NoteOpacity(lane, now)`，只乘 alpha，不改 RGB。
- 最终 alpha = 原视觉 alpha × 轨道 NoteOpacity；与 Bad/Miss 淡出、长条尾部渐隐叠加。
- 纯视觉：不影响判定与计分；NoteOpacity = 0 时 Note 不可见但仍可打。
- 不影响打击/丢失 VFX（VFX 独立）。
- Fake Note 同样受 NoteOpacity 影响。
- 用 `MaterialPropertyBlock` 写入，避免材质实例化。

### 默认值

| 通道 | 默认 |
|---|---|
| Position / Rotation | (0,0) / 0 |
| Head/Line/Label Opacity | 0（沿用旧行为；谱面需用 Opacity 事件亮起） |
| Note Opacity | **1**（新运行时要把 NoteOpacity 应用到 NoteView，若默认 0 会导致无 Opacity 事件的谱面 Note 全部不可见） |
| Length | 1 |
| Speed | `Multiplier 1`（= 玩家全局流速） |
| Zone | `All` |
| Parent | null |

### API 建议

```csharp
public sealed class LaneState
{
    public LaneState(IReadOnlyList<LaneEvent.Transform> transforms, IReadOnlyList<LaneEvent.Opacity> opacities,
                     IReadOnlyList<LaneEvent.Length> lengths, IReadOnlyList<LaneEvent.Speed> speeds,
                     IReadOnlyList<LaneEvent.Zone> zones, IReadOnlyList<LaneEvent.Parent> parents);

    public LaneFrame GetFrame(int laneIndex, int time);      // 含 Parent 合成的世界坐标/旋转
    public float HeadOpacity(int laneIndex, int time);
    public float LineOpacity(int laneIndex, int time);
    public float LabelOpacity(int laneIndex, int time);
    public float NoteOpacity(int laneIndex, int time);
    public float Length(int laneIndex, int time);
    public LaneSpeedSample Speed(int laneIndex, int time);   // { LaneSpeedMode Mode; float Value; }
    public JudgeZone Zone(int laneIndex, int time);
    public int? Parent(int laneIndex, int time);
}

public readonly struct LaneFrame { public Vec2 Position; public float Rotation; }
```

**Parent 合成**：

- 合成在 `GetFrame` 查询时递归完成，构建/曲线解析阶段不展开父链；X/Y/Rotation 通道始终存局部值。
- 只合成 Position/Rotation；Speed、Length、Opacity、Zone 不继承。
- 公式（从根到叶累加）：

```
worldPos = parentPos + Rotate(localPos, parentRot)
worldRot = parentRot + localRot
```

- 不设最大深度；检测自引用、环、无效父级（轨道不存在等）。遇到时在该处终止合成链，保留已合成的帧，不中断播放。
- 设置 Parent 的瞬时，坐标语义由世界坐标切换为相对坐标，允许出现跳变（正常行为）。
- 「XY 是否随父线旋转」属性本次不实现：子线位置偏移始终随父线旋转（纯刚性合成）。已记录到 `CURRENT_TASK.md` 待做，未来新增 `bool` 属性（默认 true；false 时仅继承平移，自身 Rotation 仍继承父旋转）。

**JudgeZoneConfig（Unity 侧）**：

```csharp
[Serializable]
public struct JudgeZoneConfigData
{
    public JudgeKeyAction L1;   // 单键
    public JudgeKeyAction L2;
    public JudgeKeyAction R1;
    public JudgeKeyAction R2;

    public JudgeKeyAction[] ExtraLeft;
    public JudgeKeyAction[] ExtraRight;
    public JudgeKeyAction[] ExtraAll;
}
```

物理键位（`InputActions`）：`L2 = D（左外侧）`、`L1 = F（左内侧）`、`R1 = J（右内侧）`、`R2 = K（右外侧）`；资产中的 L1/L2/R1/R2 字段必须按此语义配置。

派生规则：

| Zone | 键集合 |
|---|---|
| L1 | `{L1}` |
| L2 | `{L2}` |
| R1 | `{R1}` |
| R2 | `{R2}` |
| Left | `{L1, L2} ∪ ExtraLeft` |
| Right | `{R1, R2} ∪ ExtraRight` |
| All | `Left ∪ Right ∪ ExtraAll` |

- 全部去重；`JudgeZoneCatalog.Keys(JudgeZone)` 返回 `JudgeKeyAction` 集合（供判定使用）；`InputKeys(InputZone)` 返回互斥的输入分区集合（供 TrackController 收集，同一按键只归首个分区）。
- L1/L2/R1/R2 允许重复；配置缺失或包含未定义的 Action → 初始化直接失败（抛异常）。
- 无 Zone 事件时默认 `All`，使用上表的 All 集合。
